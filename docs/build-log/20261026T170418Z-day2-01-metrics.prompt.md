BUILD backend/aria_home/metrics.py (pure functions, no I/O, no model calls):
1. `temperature_trend(records, zone, start, end, now)` over thermostat indoor_temp records for
   one zone, using only records visible at `now` (received_at <= now) and observed within
   [start, end]: returns sample_count, coverage (share of the window spanned by samples,
   0..1), largest_gap_s, first/last value and time, change, rate_per_hour, unit, and
   `sufficient` (False when fewer than 3 samples or coverage < 0.5). Missing values (None) are
   skipped and counted as `missing_count`, never treated as 0. Convert C to F explicitly when
   units are mixed, and record that a conversion happened. Duplicate ids counted once.
2. `target_gap(trend, target_temp, target_unit)`: latest value minus target, with units
   reconciled; None when the trend has no samples.
3. `circuit_activity(records, circuit_id, start, end, now, noise_floor_w)` over circuit_power
   records: sample_count, coverage, largest_gap_s, max_w, mean_w, `active` (any sample above
   noise_floor_w), and the binding status from the records (confirmed / candidate / unknown).
   NEVER claim heat delivery: the result has a fixed field
   `meaning: "electrical activity only; not proof of useful heat"`.
4. `NOISE_FLOOR_W` constant (document it as a configured value, e.g. 15 W, not tuned on data).

Add `GET /api/metrics?at=<ISO>` to backend/aria_home/app.py returning, for the demo scenario:
the indoor trend over the 3 hours before `at`, the target gap against the homeowner's confirmed
target, and circuit activity for every circuit in the scenario over the same window. Include
`"data_mode": "synthetic"` and `"computed_by": "deterministic code"`.
