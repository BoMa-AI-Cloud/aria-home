PURPOSE: help tell a heating-specific discrepancy apart from a broader power or monitoring problem,
as supporting context. It is NOT an outage detector. It never claims other circuits rule out an
outage.

RULES (enforce in code):
1. Fresh activity on other circuits weighs against complete loss of power during the window,
   subject to source validity and backup arrangements.
2. It does not exclude a lost service leg, a breaker or equipment-supply problem, or an earlier
   or intermittent outage.
3. Missing readings mean lost visibility, not power loss. Zero branch use alone does not prove
   an outage. "No activity observed" and "no fresh data" are different states.
4. Never "normal" (no validated baseline exists). Idle circuits are not abnormal.
5. Channels from one meter are correlated: count them as ONE lineage, never as independent
   confirmations.
6. A calculated or stale value is never a fresh measurement. Mains/leg data are used only if
   actually measured and fresh; the demo has none, so mains = not_available.
7. Heating-specific statements need a confirmed equipment binding; candidate/unknown -> none.
8. Backup configuration unknown is always a stated limitation unless known.

BUILD backend/aria_home/power_context.py with `power_context(records, window_start, now,
noise_floor_w, backup="unknown")` returning a pydantic model:
- per_circuit: circuit_id, binding status, status one of fresh_active | fresh_quiet | stale |
  missing | invalid | conflicting (use evidence.freshness at `now`), age_s, last value.
- lineage: meter id(s) from provenance/subject (one lineage in the demo), counts by status,
  share of the window covered (reuse metrics coverage), largest gap.
- mains: not_available | measured_fresh | measured_stale | calculated_only.
- heating_binding: confirmed | candidate_only | unknown (from the circuit bound to equipment
  "furnace", if any).
- backup: known_none | known_present | unknown.
- continuity: activity_weighs_against_total_loss | visibility_lost | insufficient_evidence |
  conflicting_evidence.
- statement: built from computed fields. For the demo it must read exactly:
  "Fresh activity is observed on other monitored circuits. This weighs against complete property
  power loss during this window, but does not independently confirm power to the heating
  equipment."
- limitations (always non-empty): "Cannot exclude a lost service leg." (dropped only when both
  legs are measured, fresh and nonzero); "Breaker or equipment supply problems are not observable
  from branch readings."; "Interruptions outside this window are not covered."; and "Backup-power
  configuration unknown." when backup is unknown.
- BANNED_PHRASES constant: "power is normal", "no outage", "outage confirmed", "breaker tripped",
  "the furnace has power". A test asserts none appears (case-insensitive) in any generated text.

Add GET /api/power-context?at=<ISO> for the demo (window: 3 h before `at`), with
