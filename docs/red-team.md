# Red-team notes (illustrative unless a recorded run backs it)

Each row pairs a "without this rule" behaviour with the test that proves ARIA Home's actual behaviour. Rows marked **ILLUSTRATIVE** describe a hypothetical failure mode for reasoning only — no recorded run shows ARIA Home doing that, and no recorded run shows another system doing it. Rows marked **RECORDED** point at the recorded evidence file.

| # | Without this rule (hypothetical) | Status | ARIA Home rule | Proving test |
|---|---|---|---|---|
| 1 | An HVAC request could carry the homeowner's itinerary, email or live location to a contractor. | ILLUSTRATIVE | Per-audience allowlists in code; HVAC payload is exactly property label, access note, manager contact label and relevant observations; forbidden keys are refused and refusals are recorded. | `backend/tests/test_audit3_group4_safety.py::test_hvac_payload_excludes_sensitive_fields_and_refusals_recorded`; `backend/tests/test_audit3_group4_fields_audit.py` vs `docs/fields-audit.json` |
| 2 | Circuit watts (e.g. a blower at 400–600 W during an outage) could be read as "the heating is working". | ILLUSTRATIVE | Watts never prove useful heat; `useful_heat` is supportable in no condition, and electrical-only never yields `on_track` or a warming stage. Only temperature evidence can show warming. | `test_audit3_group4_safety.py::test_electrical_alone_never_on_track_or_warming_and_single_source_limits` |
| 3 | A stale thermostat reading could be presented as the current temperature during an outage. | RECORDED: live rejections for citing stale/superseded readings as current are in `backend/eval/results-live-current.json` | Thermostat-only at `demo_video_v1@16:31` cannot support a current-temperature claim (last reading 15:30); fresh room-sensor readings carry the picture. | Same test as #2 (thermostat-only assertions) |
| 4 | A manager clicking "acknowledge" could close the issue. | ILLUSTRATIVE | A simulated acknowledgement at 16:52 is recorded as "acknowledged, not resolved" and changes no readiness, outcome or verification stage. | `test_audit3_group4_safety.py::test_manager_ack_at_1652_changes_nothing`; `test_notifications.py::test_ack_never_changes_outcome_or_stage` |
